舊分支 `v1.0/overview`（`1b19423`）是日曆分組＋頁內捲動標亮，且基於 0.1.0。本版**不以那份 WIP 為規格**；只參考「獨立模組、只讀、零送出」的方向，實作對齊最新 main。

## 用起來應該怎樣

使用者在 x.com 任一頁打開 Dagaz 浮層，就能一眼看到所有已排程的推文：每列顯示排程時間（本地時區、含星期）與內文前幾十字，依時間先後排序，顯示總數與最近一則還有多久。不需要進 Scheduled 頁。資料來源是使用者曾經造訪 Scheduled 頁時擴充讀到的列表（既有快取機制），浮層要標明「最後同步時間」，並提供「前往 Scheduled 同步」連結；快取過期或為空時明確提示，不得把「還沒載入」當成「沒有排程」。點某一列可前往 Scheduled 頁。範圍只做總覽：不做編輯、刪除、重排，不自動開排程視窗。

## 範圍（做）

- 任一 x.com 頁打開 Dagaz 浮層即可看總覽。
- 列：本地時間（沿用 `formatTime`，含星期）＋內文前 100 個 code point。
- 依排程時間由早到晚。
- 顯示總數、最近一則（尚未到期者）還有多久、最後同步時間。
- 「前往 Scheduled 同步」：可信點擊才 `location.assign("https://x.com/compose/post/unsent/scheduled")`（與既有前往鈕同一固定目標）。點某一列同樣只做這次導覽，不捲動、不標亮、不開編輯。
- 快取三種狀態必須分開：尚未同步、已確認空列表、已過期（仍可能有過期列）。
- 在 Scheduled 頁讀到完整、非 pending 列表時寫入總覽快取；確認空列表寫入 `n=0`；載入中／解析失敗不覆蓋。
- 九語字串；浮層開合、拖動、快速時段、回覆／引用不出現快速時段等既有行為不退化。
- 版本 0.2.0。

## 資料與儲存

既有 `xsched.probe.lastScheduled` 只含最後一則時間，仍給快速時段「隨機分鐘」用，schema 不變。

新固定 key（只許 `probe/position.js`，且 SHA 鎖住）：

- key：`xsched.probe.overview`
- 僅 `hostname === "x.com"`
- 確認空：恰好 `{s,n}`，`n===0`，`s` 為同步毫秒（安全整數、>0）
- 有列：恰好 `{s,n,i}`，`n` 為 1–80 且等於 `i.length`；`i` 每項恰好 `{t,p}`（`t` 有效毫秒，`p` 字串、最多 100 code point、無控制字元）
- 拒絕多餘欄位、getter 中途變質、過長 JSON（>24576）、惡意 JSON
- 不存帳號、網址欄位、診斷；`p` 只來自當次已讀列表的本文前段（fixture／真頁都是使用者自己看過的列）
- TTL：自 `s` 起 24 小時；過期仍可讀出列，但 UI 必須標過期並請同步，不得顯示成「沒有排程」
- 整頁重載後仍顯示；SPA 切走 Scheduled 只清記憶體累加，不清這個 key
- 位置重設不清總覽

尚未寫入 key ＝還沒載入，文案必須與「已確認 0 則」不同。

## 老闆實測（≤6 步）

1. `git pull --ff-only origin main`（合併後）或載入本分支 `probe/`。
2. `chrome://extensions` 重新載入，確認 0.2.0，重新整理 x.com。
3. 打開 Dagaz：若還沒去過 Scheduled，應看到「尚未同步」而不是「沒有排程」；點「前往 Scheduled 同步」。
4. 在 Scheduled 自己捲到底，回到任一頁再打開浮層，核對則數、時間、前段文字、最近一則倒數與最後同步時間。
5. 點某一列應只進入 Scheduled，不會打開排程視窗或替你送出。
6. 開關浮層、拖動、整頁重載後總覽仍在；有問題只私下回診斷，不提交真文／帳號。
