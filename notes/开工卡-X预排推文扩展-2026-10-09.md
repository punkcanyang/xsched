## 硬规矩
- 不用 X 官方 API、不用任何 API、不连我们自己的伺服器。只改造 x.com 页面：老板照样在页面发文，扩展只帮他操作 X 原生的「排程」视窗。
- 扩展不自己定时发文、不在背景发文；真正发出去一律靠 X 原生排程。
- 不加网路请求（verify 脚本挡 fetch/XHR）；权限最小（content script 只匹配 x.com／twitter.com；资料存本机）。
- 不在共享机登入老板 X 帐号（不碰 @decoy_handle 也不碰老板个人号）；真实帐号测试一律由老板在自己的 Chrome 做。开发用本机模拟页／fixture。
- Cursor 云端 grok-4.7 high 非 Fast；复审 Opus 5.5，额度不够退 Grok 4.7 high 另开 session。
- 不碰 Chatseek 排程（1.7.1 照旧先做完）。

## 闸 0：可行性（先做，做完回报商务拓展再往下）
验证能否从 x.com 页面稳定读出「Unsent posts → Scheduled」列表（每则的排程时间、文字前段），不靠 API。给出：DOM 结构依据、读取方式、改版风险、老板实测 ≤5 步（读出来的则数与时间是否和 X 上一致）。读不出来就停，回报替代方案（例如只记本机自己排过的）。

## 1.0 要什么（闸 0 过才做）
1. 快速选时段：发文框旁加按钮，预设时段（例如 9:00／12:30／20:00，可自订、可设星期）；一按＝打开 X 原生排程视窗并填入「下一个空时段」，老板确认后照原流程按 Schedule。
2. 自动预排（可开关）：开启后按发文就改走排程，填入下一个空时段；预设关闭。
3. 空时段要避开 X 上已排的推文（用闸 0 读到的列表），不只记本机。
4. 排程总览：侧栏或页面面板，周视图／列表，显示已排推文的时间与文字前段，点击跳到 X 的 Scheduled 那则编辑。
5. 时区跟浏览器；多国语言沿用 Chatseek 那套（繁中、简中、英、日、韩为先）。
6. 健康检查：找不到 X 排程视窗或列表时，面板明确警告并有「复制诊断」（只含命中数，不含推文内容）。
